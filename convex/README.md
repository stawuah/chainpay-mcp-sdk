# ChainPay operational storage

Axum retains wallet authentication, signing, transaction validation, and recovery.
The MCP service retains its public tool and inbox interfaces. Convex stores
off-chain records; it does not submit or authorize payments.

Deploy with the root `convex.json`. Configure distinct, random service secrets
of at least 32 characters in the Convex deployment:

- `CHAINPAY_CONVEX_BACKEND_SECRET`: backend operations only.
- `CHAINPAY_CONVEX_MCP_SECRET`: connection, inbox, and rate-limit operations only.
- `CHAINPAY_CONVEX_MIGRATION_SECRET`: migration operations only; keep disabled
  during normal service by leaving `CHAINPAY_CONVEX_MIGRATION_ENABLED` unset.

The versioned endpoint is `POST /internal/storage/v1` on the deployment's
`.convex.site` URL. Supply `Authorization: Bearer <service secret>` and
`{ "operation": "...", "args": { ... } }`. Responses are `{ "value": ... }`
or `{ "error": { "code": "...", "message": "..." } }` with an error status.
Only internal functions access tables. Service credentials are never wallet
credentials; upstream services must verify the actual caller before invoking
owner-scoped operations.

Backend operation names and scalar argument names match `StatusStore`. Record
write arguments are `record_json`, `challenge_json`, or `signer_json`. These are
serialized JSON strings. Reads return the same string or null. This preserves
all nested integer values without passing them through JavaScript numbers.
Scalar u64 arguments are decimal strings. Claims use `intent_json` and
`initial_json`; owner auth uses `value_json`. Managed signer storage includes
the private provider identifiers omitted by the public Rust serializer.

MCP inbox records carry `content_json` instead of `content`. Connection records
use the registry's public camelCase shape plus `tokenHash` and `revokedAt` for
storage. These private fields are omitted from every public connection result.
Rate counters are updated atomically across instances. Challenge consumption,
idempotency-key uniqueness, and operation reservation happen in one mutation.

## Maintenance and migration

`CHAINPAY_MAINTENANCE=true` rejects every runtime write, including challenge
consumption and observation. Reads remain available. Final cutover must also
pause and drain old PostgreSQL writers before taking the source snapshot.

Migration requires both `CHAINPAY_MAINTENANCE=true` and
`CHAINPAY_CONVEX_MIGRATION_ENABLED=true`, plus the migration credential:

- `migration.import`: `{ table, rows: [sqlRowJson, ...] }` returns
  `{ imported }`. Rows are lossless SQL JSON strings using original SQL column
  names. Maximum 100 rows and 900,000 request bytes; each source row must fit
  350,000 bytes because the original and normalized copies coexist.
- `migration.export`: `{ table, cursor: null | string, limit: 1..100 }` returns
  `{ rows: [sqlRowJson, ...], cursor, done }`. Feed `cursor` into the next call
  until `done`. Export overlays current operational values on the source row,
  preserving unused SQL columns and unchanged microsecond timestamps.

Supported tables: `payments`, `transactions`, `x402_payments`,
`managed_signer_challenges`, `managed_signers`, `delivery_attestations`,
`operation_claims`, `owner_auth`, `agent_connections`, and `inbox_messages`.
Imports upsert original logical IDs, so a repeated batch is resumable. They
never invent ownership for legacy records. Disable migration mode before
reopening runtime writes. Never retry a financial side effect because a storage
request timed out: reconcile the original operation ID.

Oversized rows and counters outside JavaScript's safe integer range are rejected
explicitly during rehearsal; they are never rounded or truncated. Individual
runtime documents are capped at 900,000 encoded bytes. Owner connection lists
currently reject more than 1,000 active entries; x402 mandate filtering rejects
scans beyond 2,000 indexed owner records. These failures are explicit rather
than returning incomplete lists.

## Community pet (preview only)

`CHAINPAY_SHARED_PET=on` enables backend-only `pet.state`, `pet.visitors`,
`pet.act`, and `pet.memories` through the same authenticated storage endpoint.
MCP credentials cannot invoke them. Axum exposes the narrow walletless gateway;
pet tokens never authorize payment operations. Disable the flag to fail closed.
This feature is not deployed by implementation checks.

`shared/pet.ts` defines the public contract and deterministic simulation. The
server computes needs, elapsed naps, low-power hysteresis and timestamps.
State polls project decay without rewriting the shared world. Initialization,
daily habit evaluation and accepted actions materialize it; no active browser
or heartbeat is required. Naps last ten minutes after each four awake hours, with 0.3 decay.
A gentle wake resets the four-hour awake interval.

Visitor creation receives only SHA-256 token and trusted-peer hashes. Sessions
last 30 days. Limits are 20 new sessions per peer/minute and 200 per peer/day to accommodate
shared office and café networks, 60 actions per session/minute,
240 per peer/minute, 1,000 per session/day, plus global bounds. Accepted care
shares a 30-second cooldown for play/ball/game. Every command has a UUID v4;
replays return the original result, and changing its action conflicts. Keep
uncertain command IDs when retrying. Command records survive until session
expiry; expiry is checked before replay, so garbage collection cannot reapply
old commands. All care, dedupe, aggregates, habits, memories and rates are one
atomic mutation. No visitor identity is returned in public state or memories.

Habits evaluate once per UTC day, at its boundary, using the preceding seven
complete UTC days. Each session/activity/day contributes once; an activity
needs two distinct days. Ties retain the current favorite. These daily counts
are bounded indexed reads even as the visitor population grows. Session resets
cannot prove distinct humans; trusted-peer limits bound anonymous amplification.

Memory pagination accepts `limit` (1–50) and the previous `nextBefore` opaque
numeric cursor; it is not a timestamp. The cursor preserves simultaneous
memories while `at` remains the actual server time. The page also includes the
last seven daily action aggregates. Firsts, discoveries and recovery records
come only from accepted interactions; no fabricated initial diary is seeded.
Hide/Pin remain device preferences in the frontend and legacy saves are retained.

Run `npm run check:convex` and `npm run test:convex`. These use local
`convex-test` with simulated clocks; they do not deploy or demonstrate a live
cloud session. Cloud rollout and human usability remain pending.
